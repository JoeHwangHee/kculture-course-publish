# 0006. 상위·하위 오케스트레이터와 worker로 나눠 만들고, dryforge는 설계에만 쓴다

- 날짜: 2026-10-07 09:3x · 주체: 팀장 · 0004의 "구현·검증·검토는 dryforge `go`로"를 대신한다

## 맥락

- 0004는 작업 설계·구현·검증·검토를 모두 dryforge(`ready` → `go`)로 하기로 했다. `go`는 한 세션이 작업 그래프를 차례로 돌리고, 병렬 작업만 자기 worktree와 서브에이전트로 나눈다.
- 그러면 트랙이 여럿일 때도 한 세션이 모두 쥐고, 트랙마다 작업기록이 따로 남지 않는다. 또 `go`의 함정(작업 base가 main일 수 있음, 올리지 않은 main 커밋, 작업 트리가 깨끗해야 시작)을 당일 순서가 계속 피해 다녀야 했다.
- 팀장 지시(원문): "1. main을 상위 오케스트레이터로 잡고 하위 오케스트레이터 workspace를 생성(하위 오케스트레이터 수는 작업영향도로 판단 및 디렉토리를 app내에서 분리 생성해서 처리) 2. 각 하위 오케스트레이터는 worker 서브에이전트들을 오케스트레이트. 3. worker 서브에이전트 debugger추가. 4. 각 하위 오케스트레이터마다 작업기록 폴더를 생성 및 기록. 5. 작업기록은 각 하위 오케스트레이터가 최종 정리 및 상위 오케스트레이터에게 보고 6. 보고 및 지시문 전달은 파일생성 및 스크립트 실행. (파일은 각 작업기록 폴더에 생성. flag도 생성)"
- 이어진 질문과 답(원문): "하위 오케스트레이터 안에서 dryforge를 계속 엔진으로 쓸까요?" → "상위에서만 dryforge로 플랜. 하위는 플랜에따라 작업" / "'app 내에서 분리'를 어떻게 읽을까요?" → "worktree도 app/ 안에" / "각 트랙의 최종 작업기록을 커밋할까요?" → "최종 정리본만 커밋 (Recommended)"

## 결정

- **상위 오케스트레이터**(main 폴더의 팀장 주 세션): dryforge `ready`로 설계하고, 작업을 트랙(`app/<트랙>/`)별로 묶고, 0단계(공통 뼈대·스키마·가짜 입력·`app/pyproject.toml`·lock)를 worker로 만든다. 지시·답, 키가 닿는 명령(팀장 승인 뒤), 트랙 병합·push를 맡는다.
- **하위 오케스트레이터**(트랙마다 새 터미널 창의 Claude 세션, 최대 3개(조정값)): `app/.orch/<트랙>/wt` worktree에서 `track/<트랙>` 브랜치로 일한다. worker를 지휘하고 작업기록을 남기고 최종 보고를 정리한다. dryforge는 쓰지 않는다.
- **worker**: `.claude/agents/`의 `worker-implementer`, `worker-reviewer`, `worker-debugger`(새로 추가).
- **지시·보고**: `scripts/orch.py`가 작업기록 폴더 `app/.orch/<트랙>/log/`에 번호 붙은 본문 파일과 flag를 만든다. 기다릴 때는 `wait`를 백그라운드로 돌린다. `app/.orch/`는 git에서 뺀다.
- **기록**: 오가는 지시·보고·flag와 작업기록은 로컬에만 둔다. 하위가 정리한 최종 보고만 트랙 병합 때 `docs/tracking/tracks/<트랙>.md`로 커밋한다.
- dryforge `go`는 쓰지 않는다. main 반영은 그대로 브랜치 → 검사 → 독립 검토 → squash다.

## 버린 대안

- **하위도 dryforge `go`로 돌리기**: `go`의 검증 관문을 그대로 쓸 수 있지만, worktree에는 `.dryforge/`(설계 문서와 초기화 표식)가 없어 복사해야 하고, `go`가 끝에서 `docs/`를 고쳐 트랙끼리 부딪힌다. debugger도 `go`가 스스로 부르지 않는다.
- **worktree를 `.dryforge/worktrees/`에 두기**: main 폴더가 늘 깨끗하지만, 팀장은 `app/` 안에 두기로 했다. `app/.orch/`를 git에서 빼서 같은 효과를 낸다.
- **세션 사이 메시지(SendMessage)로 보고받기**: 파일이 남지 않고, 터미널 창으로 띄운 세션이 세션 목록에 25분 넘게 보이지 않았다.

## 결과

- 창마다 폴더 신뢰·권한 확인을 사람이 받아야 한다. 하위 수를 3개 이하로 두는 이유다.
- 트랙 worktree에는 추적 파일만 있다. 설계 내용과 자료는 지시문에 넣고, 키가 닿는 일은 상위가 맡는다.
- 트랙은 `spawn` 때의 main에서 갈라지므로, 계약·공통 파일 변경은 상위가 알리고 하위가 `git merge main`으로 받는다.
- 이번 결정으로 0004·결정 기록 05:55·08:50 줄의 `go` 규칙은 쓰이지 않는다. `go`를 다시 쓰면 그 줄들의 함정을 먼저 본다.
