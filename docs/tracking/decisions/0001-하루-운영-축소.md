# 0001. 예선 6일 운영을 하루짜리로 줄인다

- 날짜: 2026-10-06 · 주체: 팀장

## 맥락

예선(2026-09-22~28, 6일)은 첫 커밋부터 결과표까지 약 64시간이 걸렸고, 그중 문서·설계에 약 12시간, 계획 문서 11종에 약 7.5시간을 썼다 `[추론: git 커밋 시각]`. 본선 개발 시간은 7시간(10:30~17:30)이고 주제는 당일 공개된다. 예선 관행을 그대로 쓰면 접수와 문서만으로 하루가 끝난다.

## 버린 대안

- **예선 관행을 그대로 쓴다**: 문서 준비만으로 개발 시간 대부분이 사라진다.
- **관행을 모두 버리고 바로 만든다**: 예선 결과를 만든 평가 먼저·검증기·키 비보유 원칙까지 잃는다. 결과 숫자를 근거 있게 말할 수 없게 된다.
- **외부 자문 유지**: 예선에서 기다리는 동안 일이 멈췄고, 결국 반영하지 않았다 `[사실: 예선 docs/tracking/journal.md 478~484행]`.

## 결과

- 계획 문서가 없으므로 트랙끼리의 약속은 계약 문서에만 기댄다. 거기 없는 약속은 약속이 아니다.
- 봉인 자료가 없으므로 홀드아웃 보호는 "개발 중인 에이전트에게 열지 않는다"는 지시와 커밋 순서에만 기댄다. 예선 수준의 권한 분리 증거는 낼 수 없다.
- 검토자가 1명이라 도메인별 관점(데이터, 모델, 보안)이 빠질 수 있다. 키·네트워크·샌드박스 변경에만 보안 관점을 더한다.
