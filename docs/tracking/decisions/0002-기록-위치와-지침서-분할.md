# 0002. 당일 기록을 docs/tracking/으로 옮기고 지침서를 문서별로 나눈다

- 날짜: 2026-10-06 23시 무렵 · 주체: 팀장

## 맥락

전날 밤까지는 폴더 루트의 `STATUS.md`가 상태 기록이었고, `MISSION.md`·`DECISIONS.md`는 접수 때 루트에 만들 정본으로 정해져 있었다. 규칙·순서·함정은 지침서 한 파일(1,147줄)에 다 들어 있었다. 작업 설계·실행에 쓰기로 한 dryforge는 `docs/` 아래의 구성·업무 규칙·보안·작업 규칙·함정·운영·계약 문서와 `docs/tracking/`의 상태·결정·문제 기록을 읽고 고친다. 기록이 루트에 따로 있으면 작업 설계 때마다 두 곳을 맞춰 봐야 했다. 지침서를 그대로 두면 같은 규칙이 두 군데에 생겨 서로 달라질 수 있다.

## 결정

- 상태 기록은 `docs/tracking/status.md`, 결정 기록은 `docs/tracking/decisions/index.md`의 한 줄 표, 미션 원문·질문·심사 매핑은 `docs/tracking/mission.md`로 옮긴다.
- 옛 `MISSION.md`의 나머지는 성격대로 나눈다: 계약 → `docs/contracts.md`, 주장·하는 일·평가 → `docs/business-rules.md`, 실행 사슬 → `docs/architecture.md`, 트랙·파일 소유 → `docs/standards.md`, 줄일 순서 → `docs/tracking/status.md`.
- 지침서는 내용을 각 문서로 나눠 옮기고 파일은 없앤다.
- 기록 파일 예외(검토 없이 main에 바로 커밋)는 새 경로의 상태 기록과 결정 기록 표에 그대로 적용한다.

## 버린 대안

- **루트 세 파일을 정본으로 유지**: 전날 밤에 고칠 곳이 가장 적었다. 그러나 작업 도구가 읽고 고치는 기록 위치와 달라, 작업 설계 때마다 두 곳을 함께 봐야 한다.
- **지침서를 그대로 두고 핵심만 옮긴다**: 전날 밤 작업이 적다. 그러나 같은 규칙이 두 곳에 남아, 당일 한쪽만 고치면 에이전트마다 다른 규칙을 읽는다.
- **미션 접수 기록 한 파일에 계약까지 둔다**: 접수는 빠르지만 계약 정본이 계약 문서와 겹친다.

## 결과

- 미션 접수 결과를 한 파일이 아니라 여러 문서에 나눠 써야 한다. 운영 문서의 미션 접수 절차에 쓸 곳을 적어 두었다. 이 문서들은 기록 파일 예외 밖이라 접수 결과는 브랜치·검토를 거쳐 병합한다.
- 예선 저장소와 옛 커밋에 남은 "지침서 n절" 표기는 이제 가리킬 곳이 없다. 새 문서는 절 번호 대신 내용을 직접 적는다.
- 옛 지침서는 git 이력(커밋 `425ad90`까지)에서만 볼 수 있다.
