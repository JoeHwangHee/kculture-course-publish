# 0005. 상태·결정 기록만 바꾸는 커밋은 검토 없이 main에 바로 넣는다

- 날짜: 2026-10-06 22시 무렵(커밋 `4d8be58`) · 주체: 팀장

## 맥락

main 반영은 작업 브랜치 → 검사 → 독립 검토 → squash 병합이 원칙이다. 상태 기록과 결정 기록은 하루에도 수십 번 바뀐다. 매번 브랜치와 검토를 붙이면 시간만 들고, 기록이 늦게 반영돼 에이전트들이 옛 상태를 읽는다.

## 결정

`docs/tracking/status.md`와 `docs/tracking/decisions/index.md`만 바꾸는 커밋은 팀장의 주 에이전트 세션이 `python3 scripts/secret_scan.py` 종료 코드 0을 확인한 뒤 main에 바로 커밋한다. 독립 검토는 생략한다. 다른 파일이 하나라도 섞이면 예외가 아니다.

## 버린 대안

- **기록도 모두 검토를 거친다**: 원칙은 하나로 유지되지만 기록이 늘 뒤처진다.
- **기록을 커밋하지 않고 작업 폴더에만 둔다**: 빠르지만 다른 worktree·세션에서 보이지 않고, dryforge `go`가 커밋 안 된 수정을 보고 멈춘다.

## 결과

- 기록 파일에 들어간 잘못된 내용은 검토 없이 main에 남는다. 비밀값 검사만이 관문이다.
- 미션 접수 기록, 계약, 평가 파일, 코드, 다른 문서는 이 예외를 쓸 수 없다.
