# 개발 로드맵(2026-10-07 본선)

worker와 하위 오케스트레이터가 읽는 로드맵이다. 설계 원본은 상위 오케스트레이터의 로컬 설계 문서다. 그 문서는 git이 추적하지 않아 트랙 작업 사본에는 없고, 이 문서가 그 요지를 커밋한 것이다. 계약 값은 `docs/contracts.md` 6절이 정본이다. 셋이 다르면 설계 원본 → 계약 → 이 문서 순으로 따르고, 상위에 `request`로 알린다.

권위 순서(팀장 지시): 팀장이 공유한 대화 > 팀장 지시 > `docs/`의 다른 문서(참고 자료). 비밀값 규칙과 정직한 주장 규칙은 늘 지킨다.

## 1. 만드는 것

**한 문장(팀장 확정)**: K-콘텐츠를 보고 온 방문객이 목표를 말하면, 배경지를 잇는 코스를 짜고 각 장소 이름의 유래를 근거 등급과 함께 알려주는 에이전트.

**시연 문장(심사용 주기능)**: "케데헌 보고 왔어요. 오후 3시간, 혜화에서 시작할게요"
- 목표 해석
- 테마 팩에서 장소 선택
- 역명과 유래 조회
- 작품 속 이름·옛 이름·현재 이름 정리
- 등급 부여
- 코스 파일 저장
- 게시 요청(OpenShell이 막음 → 팀장 승인 → 통과)

**구조**(모두 OpenShell 샌드박스 `kculture` 안)
```
요청 → Nemotron(라우터): 무게만 판단(heavy / light)
        ├─ 판단 실패(1회 다시 보낸 뒤) → "응답 불가" 출력 (UNAVAILABLE)
        ├─ light → Nemotron이 자료 없이 답, 첫 줄 "자료 근거 없음(일반 안내)" (ANSWERED_LIGHT)
        └─ heavy → 계획(Nemotron) → 코드가 도구 11개를 실행
                   지식 색인(JSON DB) 검색, 장소 선택(구간 이동 시간은 Nemotron이 자료를 조사),
                   이름 정리, 등급, 코스 저장, 게시 요청
모든 판단·도구 호출 → trace.jsonl(해시 사슬) / OpenShell 로그·정책 이력 → 사후 감사
```

## 2. 원칙

- **실행 경계**: Runtime policy(실행 중 강제 정책)와 경계가 가장 중요하다. 막는 주체는 모델이 아니라 OpenShell이다.
- **사후 감사**: 무엇이 언제 허용·거부됐는지 되짚을 수 있어야 한다.
- **의사결정 확인**: 에이전트가 왜 그 장소·근거·등급을 골랐는지 남긴다.
- **Agent-Native Infrastructure**: 로컬(맥 + colima + OpenShell)에서 돌린다. 접속·재현 방법을 README에 적는다.
- **Deployment Flexibility**: 모델 호출은 하나의 정책 층(OpenShell) 아래에서만 나간다. 허용 목록 방식이라 필요한 경로를 하나씩 열고 이유를 적는다. 14:35 결정으로 Claude를 빼서 모델 경로는 NIM 하나다.
- **Deterministic Governance**: 기본 거부. 등급, 시간 합계·예산 검사, 한도는 코드가 정한다. 모델은 해석·선택·요약, 그리고 구간 이동 시간 조사만 한다.

## 3. 트랙

| 트랙 | 범위 | 하는 일 | 끝 조건 |
|---|---|---|---|
| `retrieval` | `app/retrieval/` | JSON 색인(형식 판 3), 출처 메타데이터(머리 정보 > `_collection.json` > 기본값), `get_chunk`·`chunks_where`, `theme_packs`·`_collection.json` 색인 제외 | 가짜 입력 색인·검색에서 출처 키가 나옴, 시험 종료 0 |
| `tools` | `app/tools/` | 도구 11개(`select_places`, `lookup_station`, `lookup_origin`, `lookup_operating`, `organize_names`, `grade_evidence`, `save_course`, `request_publish`, `search_db`, `list_input`, `read_file`)와 `register_all` | 가짜 입력으로 예산 안 코스·충돌·운영 판정 두 경우·게시 차단·읽기 거부, 시험 종료 0 |
| `loop` | `app/loop/` | Nemotron 라우터, 가벼운 경로, 계획 받기·검사, 실행기(다시 계획 1회, 한도), 게시 대기·다시 보내기, 의사결정 기록, CLI `ask`·`publish`·`baseline` | 가짜 전송 계층으로 주요 경로 시험, 시험 종료 0 |

**상위가 맡는 것**
- 공통 뼈대: `app/common/`의 스키마·상태값·한도·도구 접점, 가짜 입력, `app/conftest.py`
- `app/pyproject.toml`·`uv.lock`
- `app/sandbox/`: 정책 두 파일, 위반 시험, 감사·시연·색인 스크립트
- `app/index/`(구운 색인), `app/data/`(대량 원자료)
- 평가, 샌드박스 재생성, 키가 닿는 명령

**트랙끼리 만나는 법**
- `app/common/tooling.py`의 등록표·`RunContext`·`Deps`로만 만난다(계약 6절).
- 다른 트랙 병합 전에는 가짜(가짜 도구, 가짜 검색기, 가짜 모델 응답)로 시험한다.

**시험**
- `app/<패키지>/tests/`에 둔다.
- `app/`에서 `env -u NVIDIA_API_KEY -u ANTHROPIC_API_KEY -u GITHUB_TOKEN uv run pytest`로, 키·네트워크 없이 돈다.

## 5. 데이터

1. **sweat 더미데이터**: Hustler가 `data/sweat/`에 계약 형식으로 만든다(조사 묶음 `kdh_pack/`에서 변환).
2. **대량 자료**: `app/data/bulk/`에 넣는다. 첫 자료는 서울교통공사 역명 유래 CSV(서울 열린데이터광장 OA-12036)다.
3. **지식 색인**: 1과 2로 호스트에서 미리 만든 JSON 색인 `app/index/kb/`. 이미지에 읽기 전용으로 굽고 커밋한다.
4. **`/hackathon/input`**: 요청에 따라 주어지는 자료다. 색인하지 않고 `list_input`·`read_file`로 직접 읽는다. 최종 시험 때는 함정 데이터(공통 시험 저장소)다.

지킬 것
- 함정 데이터의 `MANIFEST.csv`·`restricted/`·`secrets/`는 열지 않는다.
- 조사 묶음의 메모(`traps.md`, `open_questions.md`, `_parts/`, `BRIEF.md`)는 색인에 넣지 않는다.

## 6. 숨기는 것

- 평가 사례·기대 결과는 git에 없고, 저장소 밖에 있다. 찾거나 열지 않는다. 평가 방법(무엇을 재나)은 이 문서 7절에 있다.

## 7. 평가로 재는 것(사례 내용은 없음)

- 경계 시험(예측과 실측)
  - 승인 전 게시는 거부, 승인 뒤 게시는 허용
  - secrets·restricted 거부
  - 비허용 호스트·경로·실행 파일 거부
  - 샌드박스 안에서 정책을 못 바꿈
  - 샌드박스 안 실제 키 0건
- 기록 점검
  - 실행마다 기록이 있고 해시 사슬이 이어짐
  - 인용 근거가 실재함
  - 등급을 다시 계산해도 같음
  - 게시 시도마다 OpenShell 로그에 짝이 있음
- 기능 평가: 결정적 채점, x/N과 Wilson 95% 구간. 기준선은 Nemotron 단독(자료·도구 없음)이다.
- 심사 기준 점검과 제출물 목록

## 8. 하지 않는 것

- 실제 예약·결제·발송. 게시는 승인 뒤 GitHub 이슈 하나뿐이다. 승인은 시연 동안 열고 끝나면 회수한다.
- 웹 검색. 근거는 지식 색인과 `/hackathon/input`뿐이다.
- 실행 중 색인 만들기, 입력 자료 색인.
- 화면(UI) 개발, NemoClaw, 파인튜닝("학습"은 인덱싱).
- 앱 코드가 secrets·restricted를 먼저 거르는 것. 막는 주체는 OpenShell이다. 단 `read_file`은 `/hackathon/` 밖을 열지 않는다.

## 9. worker 금지 문장(지시문마다 넣는다)

- "`.env`를 열거나 출력하지 않는다. 키 값을 드러낼 수 있는 조회를 하지 않는다."
- "지시문의 범위 안 파일만 고친다. push·PR·병합을 하지 않는다. 스테이징은 `git add <파일>`로만 한다."
- "사람에게 직접 묻지 않는다. 막히면 추측하지 말고 `NEEDS_CONTEXT`나 `BLOCKED`로 돌아온다."
- "평가 홀드아웃 사례와 기대 결과를 열지 않는다."
