# 보안 정책: 키, 샌드박스, 화면

근거 표시: `[사실: 출처]` · `[추론]` · `[DESIGN]`(팀 규칙) · `[미확인]`. 출처 경로는 예선 저장소 루트 기준이다. 명령에는 실행 여부를 붙인다: `[예선 실행]`(예선에서 돌려 결과가 기록됨), `[문서만]`(실행 기록 없음, 처음 쓸 때 결과를 확인).

## 1. 지키는 것

| 자산 | 왜 지키나 | 있는 곳 |
|---|---|---|
| NVIDIA API 키(`NVIDIA_API_KEY`) | 팀장 계정에 묶인 NIM(NVIDIA의 OpenAI 호환 추론 API) 호출 권한 | 폴더 루트 `.env` 한 곳 |
| NGC API 키(셀프호스팅 NIM에 필요) | 같은 등급의 비밀값 | 아직 없다. 쓰게 되면 넣는 방법을 팀장에게 먼저 묻는다 |
| OpenClaw 게이트웨이 토큰 | 관리자 권한과 같다 `[사실: docs/research/01-제안서-초안.md 152행]` | 대시보드 주소, 샌드박스 안 `/sandbox/.openclaw/openclaw.json` |
| provider(OpenShell에 등록한 자격 증명 묶음) 설정과 게이트웨이 DB·설정 파일 | 실제 키가 들어 있다 | OpenShell 게이트웨이(호스트의 Docker 안) |
| 평가 홀드아웃과 기대 결과 | 개발 중인 에이전트에게 보이면 평가가 무효가 된다 | 미션 접수 때 정한 위치 |

**이 규칙은 두 사람(팀장, Hustler)과 두 사람이 띄우는 모든 에이전트·서브에이전트에 똑같이 적용된다.**

## 2. 키 경로(만들기부터 버리기까지)

1. **발급**: 팀장이 build.nvidia.com/settings에서 발급한다. 지금 키는 2026-10-06에 새로 발급했고 NIM 호출 `HTTP 200`을 확인했다.
2. **보관**: 원본은 폴더 루트 `.env`에만 둔다. git이 추적하지 않는다(`.env`, `.env.*`가 무시 대상이고 `.env.example`만 예외다).
3. **사용**: 키 래퍼(`scripts/with_nvidia_key.py`)가 `.env`에서 `NVIDIA_API_KEY` 한 줄만 읽어 자식 프로세스 환경에만 넣는다. 키를 디스크에 쓰지 않는다. 자식 출력에 키와 같은 문자열이 나오면 `***REDACTED***`로 가린다. 키의 앞 10글자나 끝 6글자 조각이 보여도 가리고, "키 노출 의심" 경고를 남긴다.
4. **샌드박스 안**: 실제 키는 없다. 환경변수에는 자리표시 값 `openshell:resolve:env:<변수 이름>`만 있다. 코드가 이 값을 `Authorization: Bearer` 헤더에 실으면, 샌드박스 밖에서 root로 도는 감독 프로세스의 프록시가 요청 시점에 실제 키로 바꾼다. 예선 실측에서 샌드박스 사용자 권한으로 닿는 곳의 실제 키는 0건이었다 `[예선 실행: artifacts/openshell/violation_tests.md]`.
5. **교체**: 키를 바꾸면 provider도 갱신해야 샌드박스가 새 키를 쓴다. 명령은 `openshell provider update <이름> --credential <키 이름>`이고 키 래퍼로 돌린다. 2026-10-06 22:5x에 provider 2개(`tradesentry-nvidia` ← `NVIDIA_API_KEY`, `nvidia-prod` ← `--export-as NVIDIA_INFERENCE_API_KEY`)를 새 키로 갱신했다(팀장 승인, 둘 다 종료 0). 갱신한 provider를 붙인 샌드박스가 샌드박스 안에서 NIM 200을 내는지는 아직 확인하지 못했다 `[미확인]`.
6. **폐기**: 예선 키는 팀장이 build.nvidia.com에서 폐기한다(폐기 여부 미확인). 노출이 의심되는 키는 그 자리에서 폐기하고 새로 발급한 뒤 provider를 다시 갱신한다.

## 3. 누가 무엇을 할 수 있나

| 주체 | 할 수 있는 것 | 할 수 없는 것 |
|---|---|---|
| 팀장 | `.env`에 키 넣기, 키가 닿는 명령 승인·실행, 라이선스 고지 수락, provider 만들기·갱신, 키 폐기, 비공개 저장소 만들기·초대, main push(팀장의 주 에이전트 세션이 해도 된다) | — |
| Hustler | 키가 닿지 않는 작업, `hustler/` 브랜치 push | `.env` 열기·만들기, 키가 닿는 명령 실행, main push·병합, 저장소 설정·초대 변경 |
| 하위 오케스트레이터와 worker(팀장 노트북의 트랙 세션) | 키 없이 시험 돌리기, 키가 닿는 일을 `request`로 상위에 요청하기 | 아래 "에이전트" 줄의 금지 전부, 키가 닿는 명령 실행(팀장 승인이 있어도), 상위 폴더의 `.env`를 경로로 가리키기(worktree가 main 폴더 안에 있어 경로로는 닿는다. 막는 것은 이 규칙뿐이다) |
| 에이전트(누구의 세션이든) | 키 래퍼로 키가 닿는 명령을 **팀장 승인 뒤에** 돌리기(팀장 쪽 상위 오케스트레이터만. Hustler 쪽 세션과 하위 오케스트레이터·worker는 돌리지 않는다), 키 없이 시험 돌리기 | `.env` 열기·출력, 키 값을 드러낼 수 있는 조회(환경변수 전체 출력 등), provider 설정·게이트웨이 DB·게이트웨이 설정 파일 내용 읽기·출력, 라이선스·고지 대신 수락, 홀드아웃·기대 결과 열기(구현 작업일 때) |
| 샌드박스 안 프로세스 | 정책이 허용한 실행 파일로 허용한 목적지·경로만 호출 | 실제 키 보기, 허용 밖 목적지·실행 파일로 외부 전송 |

**키가 닿는 명령**: provider 만들기·갱신, NemoClaw 온보딩, 실제 NIM 실행. 모두 팀장 승인 뒤 키 래퍼로 돌린다.

**키 값을 넣지 않는 곳**: 코드, 문서, 커밋, PR, 로그, trace(실행 추적 기록), 다른 에이전트에게 주는 지시. 지시에는 "키는 키 래퍼가 환경변수로 넘긴다"고만 쓴다.

**시험은 키 변수를 지우고 돌린다**: `env -u NVIDIA_API_KEY <시험 명령>`. 키 없이 도는 시험만 시험으로 친다. 모델 응답이 필요하면 재생 실행을 쓴다.

## 4. 샌드박스 경계(OpenShell)

세 층으로 막는다 `[사실: docs/research/01-제안서-초안.md 38~45행]`.

| 층 | 하는 일 | 한계 |
|---|---|---|
| 프롬프트 | 모델에게 어떻게 행동할지 말한다(`SOUL.md`, `AGENTS.md`) | 권한을 줄이지 못한다 |
| 하네스(에이전트 실행 틀) | 도구 인가, 인자 검증, 가드레일로 형식상 허용 여부를 거른다 | 설정이 틀리거나 오염될 수 있다 |
| 커널 | OpenShell이 네트워크 네임스페이스, OPA 프록시(정책 엔진이 판정하는 중계), Landlock(리눅스 파일 접근 제한), seccomp(프로세스가 쓸 수 있는 시스템 호출 제한)로 연산 자체를 거부한다 | 허용된 능력을 조합해 생기는 해악은 막지 못한다 |

**정책 원칙**
- 외부 전송은 필요한 경로 하나만 연다. 예선은 NIM `POST /v1/chat/completions` 한 경로뿐이었다.
- 네트워크 블록에는 목적지, L7 규칙(HTTP method·path), 실행 파일을 함께 적는다. `rules`를 빼면 그 목적지가 전부 열린다.
- 해석기(node, python 등)를 허용하면 그 자손 전부가 허가를 받는다. 그래서 L7 규칙을 한 경로로 좁힌다.
- `inference.local`(관리형 추론 주소)은 네트워크 정책 밖에서 처리된다. 쓰지 않으면 `openshell inference delete`로 지우고, 실행 묶음 앞뒤로 `openshell inference get`이 "Not configured"인지 기록한다.
- 샌드박스는 `--no-auto-providers`로 만들고 provider는 `--provider`로 명시해 붙인다.
- 읽기 전용 입력과 정답 차단 대상은 `/opt/...`에 둔다. `/sandbox` 아래 읽기 전용 하위 폴더는 쓰기가 허용됐다.

**차단의 증거로 치는 것**
- 정책 예측과 실제 실행 결과의 대조표(위반 시험표) + 정책 조회 + 감사 로그를 함께 둔다.
- 파일 차단은 미끼 파일(정답처럼 둔 시험용 파일)을 읽어 EACCES(권한 거부)가 나는 것으로 증명한다. ENOENT(파일 없음)는 증거가 아니다. 파일시스템 거부는 감사 로그에 남지 않기 때문이다.
- "종료 코드가 0이 아니다"만으로는 차단 증거가 아니다.
- "허용 목록에 있으니 안전하다"고 말하지 않는다.

## 5. 기록할 것

| 사건 | 어디에 |
|---|---|
| 키·토큰이 커밋·로그·trace·화면에 들어갔거나 그랬을 수 있다 | 즉시 팀장에게 알리고 그 일을 멈춘다. 키 래퍼의 키 조각 경고도 여기에 든다 |
| 홀드아웃이나 기대 결과가 개발 중인 에이전트에게 드러났다 | 즉시 팀장에게 알린다 |
| 정책 적용·변경 | OpenShell 감사 로그의 `CONFIG:LOADED … Policy reloaded successfully` 행과 Version 번호 |
| 거부된 네트워크 접근 | 감사 로그 `NET:OPEN … DENIED`, `HTTP:<method> … DENIED … engine:l7` 행 |
| `inference.local` 경로 상태 | 실행 묶음 앞뒤 `openshell inference get` 출력 |

## 6. 커밋 전 비밀값 검사

- push 전 검사는 의무다. 범위의 커밋별 diff 전체에 `scripts/secret_scan.py <범위>`를 돌린다. 뒤 커밋에서 지운 값도 앞 커밋 diff에 남기 때문이다.
- 이 검사는 키 모양, 공공데이터포털 서비스키 파라미터 모양, 로컬 절대 경로(사용자 홈, macOS 임시 폴더, 물결표로 시작하는 홈 경로)를 찾는다. 걸린 곳은 `파일:줄 종류`만 내고 행 내용은 내지 않는다.
- 문서·커밋·로그에 로컬 절대 경로, 키 값, 사람 이름(공개 저장소 주소의 계정 이름은 예외), 다른 팀 이름을 쓰지 않는다. 경로는 `<colima Docker 소켓>`처럼 자리표시로 쓴다.

## 7. 화면·녹화·발표

가린다:

- 터미널 프롬프트의 사용자 이름
- 알림
- 관리자 화면의 내부 값(접어 둔다)

## 8. 공개

- 원격 저장소는 **비공개** GitHub 저장소로 정했다(2026-10-07, 팀장). 만들기·초대·공개 범위 변경은 팀장이 정한다(실행은 팀장의 주 에이전트 세션에 맡길 수 있다). Hustler 계정에는 쓰기 권한을 주되, main push는 팀장 쪽 세션만 한다.
- push 전에는 그 범위에 비밀값 검사를 돌린다(처음 올릴 때는 `python3 scripts/secret_scan.py main`으로 main 이력 전체, 그 뒤 main은 `origin/main..main`, Hustler 브랜치는 `origin/main..HEAD`). 비공개여도 push한 내용은 GitHub에 남고, 나중에 공개로 바꾸면 이력 전체가 드러난다.
- 공개 저장소라면 main에 병합하는 순간 공개된다.
